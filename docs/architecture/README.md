# Architecture Decision Records (ADRs)

Record consequential engineering choices in this directory so future coding agents and contributors can understand **why** a design was selected.

## Convention
Use sequential files such as `0001-monorepo-and-lab-boundaries.md`. Each ADR includes:
- Status: proposed, accepted, superseded or deprecated
- Date
- Context and problem
- Decision
- Alternatives considered
- Consequences and trade-offs
- Follow-up work

Update `docs/PROGRESS.md` when a decision changes implementation priorities. Do not silently overwrite accepted decisions; supersede them with a new ADR.
